# 麦门显微镜 · McDonald's Microscope

> 把一单麦当劳拆开给你看。

一个基于**麦当劳中国官方 MCP**（`mcd-mcp`）的消费与营养透明化 Skill。它不帮你点餐，也不替你省钱 —— 它做一件更基础的事：**把官方已经公开、但没人替你摊开的数据，算清楚给你看。**

**核心模块：营养性价比地图。** 把度量单位从「多少钱」换成「**每 1 元买到多少克蛋白质**」，给出一张按性价比排序的菜单地图，再用热量密度和钠做交叉约束。

**所有数字都来自官方接口实测。模型只负责解读，不负责算数。**

## 它实测出了什么

以下每一条都是真实跑出来的，不是示意数据。样本门店：麦当劳深圳北站站内一店（`storeCode=1420227`），实测时间 2026-10-16。

### 1. 「三件套」只比单点便宜 5 毛钱

| 方案 | 官方算价 |
|---|---|
| 巨无霸三件套 | ¥54.50 |
| 巨无霸 ¥29.00 + 中薯条 ¥14.50 + 可乐 ¥11.50 | **¥55.00** |

省了 **¥0.50**。

"三件套"三个字给人的心理暗示是"打包更划算"，但在这家店，它几乎等于原价。**这套对比，此前没有任何一个工具替用户算过。**

### 2. 海报价「26.9 元起」，门店标价 53 元

`campaign-calendar` 拉到的活动原文写着：

> 龙焰鸡腿堡三件套 **26.9 元起** 即刻开吃

而同一时期，`query-meals` 里这家店「龙焰鸡腿堡三件套」的标价是 **¥53.00**。

差的不是一半的价钱，是**一个前置条件**：海报价需要凭券 / 麦金卡 / 早餐卡才能触发。显微镜做的事就是把条件标出来 —— 你有券是多少，没券是多少。

### 3. 套餐里有些东西，不加钱就能换

从 `query-meal-detail` 的 `rounds[].choices[]` 里，把所有 `diffPrice` 为 `+ ¥0` 的选项捞出来：

| 换购位 | 默认给的是 | 不加钱可换 |
|---|---|---|
| 套餐内小食 | 中薯条 | 小杯玉米杯 |
| 套餐内饮料 | 可乐中杯 | 无糖可口可乐中杯、雪碧中杯 |

菜单上不提示、点餐页要一层层点开才能看到。换成无糖可乐，**价格不变，糖归零，热量少 147 kcal**。

### 4. 积分是有寿命的

`query-my-account` 会一次性告诉你四个数字：可用多少、本月将过期多少、下月将过期多少、**历史上已经过期作废多少**。

最后那个数字往往最扎人 —— 攒积分的时候觉得是资产，过期的时候才发现它一分钱都不值。

### 5. 「买蛋白质最划算的」不是汉堡，是 ¥15 的鸡排

把度量单位换成「每 1 元买到多少克蛋白质」，该门店 94 个餐品的排行是这样：

| 餐品 | 价格 | 蛋白 | g 蛋白 / 元 | g 蛋白 / 100kcal | 钠 mg |
|---|---|---|---|---|---|
| 那么大鸡排（椒盐风味） | ¥15.0 | 24g | **1.600** | 6.2 | 996 |
| 双层吉士汉堡 | ¥26.5 | 27g | 1.019 | 6.3 | 1017 |
| 双层深海鳕鱼堡 | ¥28.0 | 28g | 1.000 | 5.8 | 917 |
| 不素之霸双层牛堡 | ¥29.5 | 28g | 0.949 | 5.7 | 1012 |
| 巨无霸 | ¥29.0 | 27g | 0.931 | 5.3 | 961 |
| 麦辣鸡腿汉堡 | ¥26.0 | 24g | 0.923 | 4.9 | **1208** |
| 麦香鸡 | ¥19.5 | 15g | 0.769 | 4.1 | 731 |
| 麦香鱼 | ¥25.0 | 16g | 0.640 | 4.9 | 556 |

两个反直觉的地方：

- **冠军是 ¥15 的鸡排**，比第二名高出 **57%**；而传统认知里「健身友好」的麦香鸡、麦香鱼反而垫底。
- **麦辣鸡腿汉堡钠 1208mg** —— 性价比排第 6 看着不错，但钠接近每日推荐上限的一半。**只看一个指标会把人带偏，所以三项一起给。**

换个目标，答案还会变：增肌看性价比、减脂看蛋白密度、控钠就把钠当硬约束。**没有唯一正确答案，只有约束条件。**

## 它能做什么

| 维度 | 数据来源 | 产出 |
|---|---|---|
| **套餐拆解** | `query-meal-detail` + `calculate-price` | 套餐 vs 单点的真实差价 |
| **广告价对照** | `campaign-calendar` + `query-meals` | 海报价的达成条件与无券实价 |
| **换购暗门** | `query-meal-detail` | 所有 `+ ¥0` 可换项 |
| **券的真实可用性** | `query-store-coupons` | 该店**当前真的能用**的券 |
| **积分寿命** | `query-my-account` + `mall-points-products` | 余额 / 临期 / 已浪费 / 价值折算 |
| **营养性价比地图** | `query-meals` + `list-nutrition-foods` | 每元蛋白排行 / 蛋白密度排行 / 钠负荷 |
| **热量账** | `list-nutrition-foods` | 整单 kcal / 蛋白 / 脂肪 / 钠 |

最终输出两张可截图分享的卡片：**「麦门成分表」** 与 **「营养性价比地图」**。

## 快速开始

### 1. 申请 MCP Token

访问 **https://open.mcd.cn/mcp** → 手机号登录 → 右上角「控制台」→「激活」→ 同意服务协议 → 复制 Token。

免费，无门槛。

### 2. 配置 MCP

```json
{
  "mcpServers": {
    "mcd-mcp": {
      "type": "streamableHttp",
      "url": "https://mcp.mcd.cn",
      "headers": {
        "Authorization": "Bearer YOUR_MCP_TOKEN"
      },
      "timeout": 60000
    }
  }
}
```

把 `YOUR_MCP_TOKEN` 替换成你的真实 Token。

**WorkBuddy 用户**：左侧边栏「专家·技能·连接器」→ 连接器页签 → 右上角「自定义连接器」；或直接在 MCP 服务管理面板点「+ 添加 MCP」粘贴上面的 JSON。保存后**需要重启 WorkBuddy** 才会加载。

其他客户端（Cursor / Cherry Studio / Trae / VSCode）配置方式相同，见[官方接入指南](https://github.com/M-China/mcd-mcp-server)。

### 3. 使用

把 `SKILL.md` 放进你的 Skill 目录，然后直接说：

```
帮我把巨无霸三件套拆开看看值不值
```

```
这家店的海报价是真的吗
```

```
我有哪些券快过期了
```

```
增肌的话在麦当劳该点哪个
```

```
我今天还差 60g 蛋白，怎么补最划算
```

### 4. 不装 Skill，只跑脚本（可选）

`scripts/compute_protein_value.py` 可以独立运行，**换任意门店重算排行**：

```bash
python3 scripts/compute_protein_value.py                  # 默认门店
python3 scripts/compute_protein_value.py 1122334          # 换成你的门店
python3 scripts/compute_protein_value.py --density        # 改按蛋白密度排序（减脂视角）
python3 scripts/compute_protein_value.py --json out.json  # 结果存 JSON
python3 scripts/compute_protein_value.py --help           # 看全部参数
```

门店编码用 `query-nearby-stores` 查。Token 自动从 `~/.workbuddy/mcp.json` 读取。

> **macOS 用户注意**：如果用 python.org 装的 Python 直接跑报
> `CERTIFICATE_VERIFY_FAILED`，执行 `pip install certifi` 即可（脚本会自动使用它）。
> 或者双击 `/Applications/Python 3.x/Install Certificates.command`。

## 设计原则

**1. 只读侦察，绝不代付。**
所有分析都是只读调用。涉及下单（`create-order` / `mall-create-order`）时必须用户明确确认，且只把官方支付链接交给用户，不代付。

**2. 数字来自接口，不来自模型。**
模型估价格是这类工具的常见隐患。本项目的硬规则是：**任何金额都必须由 `calculate-price` 算出**，找不到就标「未知」，不猜。

**3. 中立叙事。**
同样的数据，可以写成"帮你算清楚"，也可以写成"扒平台套路"。本项目**只做前者**。显微镜的立场是**信息透明**，不是对抗。

**4. 查不到就标未知。**
门店菜单拉不到、营养表没有该餐品、券接口返回空 —— 一律如实标注。宁可少说，不说错。

**5. 营养数据必须做口径对齐。**
官方营养表按「**份**」给（「麦乐鸡5块」「麦乐鸡4块」是两行），菜单按「**品**」给（只有一个「麦乐鸡」）。两者不是一一对应。对不上的**一律排除** —— 不允许拿同类顶替，也不允许按比例硬折算。健身类内容一旦数字有误，整个工具的可信度就归零。

## 已知的坑（写在这里省你时间）

- **一单只能用一张券**。想叠两张会直接报错 `600022`。所以策略是先定商品总量，再挑一张最优券补位。
- **已领取 ≠ 门店可用**。`query-my-coupons` 返回的是券包候选集，**不承诺可用**；必须用 `query-store-coupons` 按门店复核。
- **工作日 / 周末是两套券池**。方案必须按实际日期过滤。
- **金额单位不统一**。`query-meals` 返回**元**（字符串），`calculate-price` 返回**分**（整数）。这个坑几乎每个人都踩。
- **到店自取（`beType=1`）不能传 `beCode`**，传了直接报错。
- **WorkBuddy 的 `mcp.json` 是启动时读取的**，改完不重启不生效。
- **营养表按「份」、菜单按「品」**，两者对不齐。实测该门店 94 个单品里，16 项规格不明（如「薯条」对应中/大/小/迷你四种）、25 项无营养数据，全部排除，不估算。
- **`list-nutrition-foods` 返回的是类 CSV 文本，不是 JSON**；`nutritionDescription` 可能为 `null`，也可能含逗号，按「末 7 位是数值」切分最稳。
- **MCP 工具返回的是「说明文本 + 原始 JSON」的混合体**，不能直接 `json.loads`。要在 `## Original Response` 之后用 `JSONDecoder.raw_decode` 抠出 JSON。
